# AGENTS.md — OrbitApply Agent Architecture

This file documents how the OrbitApply agent system works for AI coding assistants and contributors.

---

## Agent Overview

OrbitApply uses 7 specialized agents coordinated by ORBI, the master orchestrator. Each agent has a `SOUL.md` file in `agents/{name}/SOUL.md` that defines its identity, rules, and output format.

## Agent Pipeline

```
User clicks Run
      │
   ORBI (orchestrator)
      │
   SCOUT (job discovery — no AI)
      │
   RECON (company intel — Haiku)
      │
   GUARDIAN (safety check — no AI)
      │
   TAILOR (documents — Sonnet)
      │
   LEDGER (pipeline tracker — no AI)
      │
   COACH (interview prep — Sonnet, triggered on stage change or on demand)
```

> **Note:** SUBMIT (Playwright form-fill), Auto-Apply, and Human Queue were removed in v1.3.0. GUARDIAN still enforces budget, rate limits, blacklist, and protected contacts.

## Key Rules for AI Assistants

- Never modify `agents/guardian/SOUL.md` safety rules
- Never set `autoSubmit: true` without explicit user confirmation
- Never touch `memory/` files — these are user's personal data
- Always read the relevant `SOUL.md` before modifying an agent service
- Job sites are configured in `src/config/jobSites.js` — not hardcoded in scout.js
- Search providers are in `src/utils/searchProvider.js` — waterfall fallback order matters
- COACH's interview questions live in `src/data/genaiInterviewBank.js` — original content only, never paste third-party question lists
- TAILOR renders PDFs via `pdfkit`; keep the `.txt` fallback path intact

## Document Positioning Structure

All documents generated by TAILOR follow a five-pillar structure defined in `agents/tailor/SOUL.md`:
- **O** — Outcome
- **R** — Revenue Lever
- **B** — Bottleneck
- **I** — Implement
- **T** — Track
